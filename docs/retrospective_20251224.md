- UI 実装の作業量と依存関係を具体的なタスク単位に割らず、着手順が不明瞭だった。

- 品質保証のためのテスト戦略を早期に決めず、実装と同時に書く体制を作れなかった。
- バックアップ運用要件を初期段階で合意せず、デフォルト実装がそのまま残った。

## 6. 改善アクション
1. UI 縦切りのミニマム実装を最優先で着手し、カード一覧＋編集＋コピーの 1 本線を完成させる（Phase 4-7 の依存を精査）。
2. サービス層に対するスモークテストを pytest で追加し、CRUD とバックアップの正常/異常系を自動化。
3. ロギング方針を決定（logger で INFO/ERROR、書き込み失敗時はバックアップリストを含めて記録）。
4. バックアップローテーションを導入（例: 日次最新のみ保持、上限 N 件、手動フルバックアップは別ディレクトリ）。
5. UI 開発のタスク分割テンプレートを用意（ビュー・コンポーネント・イベント・スタイルの 4 レイヤーで小口化）。
6. フィードバックループ短縮: 1 日 1 回のデモビルドまたはスクリーンショット共有をルール化。
